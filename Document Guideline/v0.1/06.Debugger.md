# Debugger

Debugger helps you inspect code execution while the program is paused.
The behavior inherits from JupyterLab debugger logic.
All actions are permission-gated.

## What Debugger is for

Use Debugger to:
- pause execution at breakpoints,
- inspect variables and call stack,
- step through code line by line,
- continue or stop a debug session.

## Open Debugger

1. Open a notebook/script.
2. Click **Debugger** in the left activity panel.

If kernel debugging is not supported, debug actions stay unavailable.

## Start debugging

1. Add one or more breakpoints in the code gutter.
2. Start run/debug execution.
3. Wait until execution pauses.

Expected behavior:
- Current execution line is highlighted.
- Debug controls become active.

## Manage breakpoints

1. Click gutter line to add/remove breakpoint.
2. Use **Breakpoints** list to review active points.
3. Enable/disable breakpoints when needed.

Expected behavior:
- Gutter and breakpoints list stay synchronized.
- Disabled breakpoints are visible but not triggered.

## Inspect variables

Debugger supports:
- **Tree view** for nested objects.
- **Table view** for row/column comparison.

1. Open **Variables** section.
2. Switch between tree and table view.
3. Expand objects or scan values.

Expected behavior:
- Variable values refresh at each pause/step.
- Selected frame context is reflected in variables when supported.

## Navigate execution

1. Use step controls while paused:
- **Step over**
- **Step into**
- **Step out**
2. Click **Continue** to run to next breakpoint.
3. Click **Stop** to end debugging.

Expected behavior:
- Call stack and variables update after each step.
- Stop clears active paused state.

## End session

A session ends when:
- execution completes,
- user clicks **Stop**,
- kernel/session is interrupted or restarted.

Expected behavior:
- Debug controls return to idle state.
- Active execution pointer is cleared.

## Permission notes

Apply this rule to all Debugger actions:
- permission granted: action is available,
- permission missing: action is hidden, disabled, or blocked with clear feedback.
