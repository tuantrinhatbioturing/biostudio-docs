# Common behaviors

This guideline defines shared interaction rules used across multiple screens.
Use it as a reusable reference for permission visibility and kernel/environment switching.

## View permission
![](../images/Pasted%20image%2020260327115708.png)
Users can check their current role permissions from the top-right account area.

How it works:
1. Click the role indicator (for example, `Member`, `Admin`) at the top-right.
2. Open the **My role permission** panel.
3. Review the permission list to see what actions are currently granted.

Expected behavior:
- This panel is read-only.
- Permission items are shown as enabled/disabled states.
- Close by outside click, `Esc`, or the close action.
- No data mutation happens from this panel.

## Change a kernel & environment
![](../images/Pasted%20image%2020260327115653.png)

Users can switch runtime by selecting either:
- a pre-installed environment, or
- another available kernel.

How it works:
1. Open the runtime selector from the notebook/session header.
2. Open the **Select kernel & environment** modal.
3. Choose a target environment/kernel from the left list/tree.
4. Review details on the right panel.
5. Click **Select** to apply.

Expected behavior:
- Background interaction is blocked while modal is open.
- `Select` is enabled only when a valid target is selected.
- Current active kernel/environment is clearly indicated.
- If switching can affect current execution state, show a warning/confirmation before apply.
- After successful switch, header/runtime badge updates immediately.

## Launcher

![](../images/Pasted%20image%2020260327115453.png)
Launcher is the default landing view used to help users start work quickly inside a project or workspace context.

How it works:
1. Opening a new tab shows the **Launcher** page in the content area.
2. Let users choose a quick-start action, tutorial, recent notebook, or suggested project entry.

Expected behavior:
- Quick-start actions are shown as clear cards or buttons.
- Recent notebooks are shown as shortcut cards for reopening work.
- Tutorials/help content is visible for onboarding and recovery.
- Selecting a launcher item opens the related file, flow, or creation action in the main panel.
- Launcher content should update to the current workspace/project context.
